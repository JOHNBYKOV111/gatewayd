gatewayd — самостоятельный LLM-шлюз на Go, совместимый с ядром OpenAI Chat API. Выполняет роль, аналогичную продуктовым гейтвеям, в масштабе одного инстанса (single-node). Один статический бинарник, без внешних рантаймов, предсказуемая задержка p99.

Ключевые возможности: OpenAI-совместимость: эндпоинты /v1/chat/completions и /v1/models. Поддерживается базовый текстовый чат и потоковая передача (SSE). Продвинутые фичи (tool calling, JSON mode, vision) зависят от возможностей конкретного провайдера и не гарантируются на уровне шлюза. Мульти-провайдерность с fallback: Ollama (локально), Anthropic, GigaChat (через внешний прокси gpt2giga). Для каждой модели настроена цепочка переключения: если первый провайдер недоступен, автоматически используется следующий. Клиент не замечает подмены (проверено вживую: остановка Ollama → ответ от GigaChat). Потоковая передача (SSE): выдача токенов по одному с отправкой каждого фрагмента, отмена при разрыве соединения клиента (context propagation) и терминатор [DONE]. TTFT измеряется по первому фрагменту. Виртуальные API-ключи: ключи вида gw-..., в базе хранятся в виде SHA-256-хеша, для отображения — префикс и последние 4 символа. Для каждого ключа задаются лимиты RPM/TPM и дневные/месячные бюджеты. Бюджеты и лимиты: при превышении мягкого лимита возвращается X-GW-Budget-Warning, при превышении жёсткого — 402 Payment Required. Списание бюджета выполняется атомарно (UPDATE ... RETURNING) и безопасно при одновременных запросах. Token bucket для RPM/TPM. Логирование вызовов: фиксируется каждый запрос (модель, провайдер, токены, стоимость, задержка, TTFT, ошибки). Промпты не сохраняются в открытом виде — только SHA-256-хэш. Точный кэш: кэш в оперативной памяти с TTL и вытеснением по стратегии LRU. Потоковые ответы сохраняются как списки фрагментов и воспроизводятся постранично. Метрика gw_cache_hit_ratio экспортируется на /metrics. Наблюдаемость: метрики Prometheus (/metrics), структурированные JSON-логи (slog), трассировка OpenTelemetry (span на запрос, вложенные спаны на попытки провайдеров, атрибуты key.id/model). Отказоустойчивость: circuit breaker на провайдера (closed → open → half-open), retry-транспорт с backoff на 429/5xx (только до первого байта клиенту), graceful shutdown с дожиманием in-flight запросов.

Производительность (нагрузочный тест k6, 2 одновременных клиента, 60 секунд, реальная Ollama на 4-ядерном CPU): пропускная способность ограничена скоростью модели на CPU (~60 с на ответ), а не шлюзом. Задержка самого шлюза (overhead поверх генерации): p50 = 1.32 мс, p95 = 1.94 мс. Единственный выброс (max = 1.39 с) — это первый запрос, когда модель загружалась в память (холодный старт). На прогретой модели p99 остается в пределах единиц миллисекунд. 100% успешных ответов (119 из 119). Потребление памяти: 16.7 MiB.

Тестирование и качество: Политика No Mocks: все тесты бизнес-логики выполняются на реальной инфраструктуре (Testcontainers Postgres, реальный HTTP-транспорт). Полное отсутствие заглушек для баз данных и сетевых вызовов. Покрытие тестами включает: интеграционные тесты с реальным PostgreSQL (миграции, идемпотентность, транзакции, конкурентное списание бюджетов, репозитории ключей и журнала), тесты HTTP-слоя (валидация JSON, кэш, стриминг, обрыв соединения, graceful shutdown), тесты middleware (Auth, RateLimit, Budget, TTFT, Tracing) с реальной БД, тесты провайдеров (golden-тесты Ollama и Anthropic, конвертация стримов), тесты маршрутизации (fallback, circuit breaker), Fuzz-тестирование SSE-парсера (400 000+ выполнений без крашей), детектор гонок (-race на всех тестах), govulncheck (0 уязвимостей в вызываемом коде), проверка статичности бинарника (ldd). CI/CD: GitHub Actions (сборка, vet, тесты с race и Testcontainers, govulncheck).

Демонстрация: Все проверки пройдены вживую. Скриншоты ключевых результатов (запросы к Ollama и GigaChat, дашборд Grafana, chaos-тест с падением Postgres, бенчмарки, прогон тестов) в файле .github/assets/ и встроены в README.

Статус: проект production-oriented, single-node: fallback между провайдерами (проверен), деградация при падении БД с автоматическим восстановлением (проверена), 100% успешных ответов в нагрузочном тесте, настроенный CI/CD с полным прогоном тестов. Система готова к развертыванию в конфигурации single-node. Код обеспечивает понимание конкурентности в Go, LLM-проксирования и инженерии надёжности.

Известные ограничения: лимиты скорости (token bucket) и точный кэш хранятся в оперативной памяти процесса. При запуске нескольких реплик за балансировщиком счётчики будут независимыми (фактический RPM удвоится, кэш будет промахиваться чаще). Кэш сбрасывается при рестарте процесса. Redis в текущей версии не поддерживается. Работа с GigaChat зависит от внешнего прокси gpt2giga (вне скоупа проекта).
Все проверки прогоняются в CI (GitHub Actions) и подтверждены зеленым статусом.

Стек: Go, PostgreSQL, Ollama, GigaChat (через gpt2giga), Prometheus, Grafana, OpenTelemetry, Docker. Лицензия: MIT.
